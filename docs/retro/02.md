## Findings, worst first

1. **A failing check did not stop a commit.** (`08fe603e`)
   The agent ran `make check ... && git commit`. The check failed on a JSX error and the commit still ran. The agent noticed later and amended it. A later `echo make=$?` read a pipe's exit code, not make's.
   Proposal: a pre-commit hook that runs `make check`.

2. **The `block-env.py` hook blocks too much.** (`332bdacd`, `04d5e7ba`)
   It blocked a heredoc and edits whose text only mentioned `.env`. The agent retried and worked around it. In `04d5e7ba` it then told the user "I did not read your local env file, so this is my best guess".
   Proposal: match real `.env` file paths only. Allow `.env.example`. The hook lives outside this repo (user scope). This repo cannot fix it.

3. **Tickets drift from the code.** (`04d5e7ba`)
   Tickets `20`, `21` and `22` were built but showed `ready-for-agent`. Tickets `14` and `03` said `done` with open boxes. This is retro 1 finding 1. The rule in `docs/agents/issue-tracker.md` and the test in `api/tickets_test.go` came from it.
   Open: the test checks the `Status:` value, not whether the value fits the boxes. A rule such as "`done` means no open boxes" could be added. I did not check ticket `03`.

4. **Ticket location is easy to get wrong.** (`1b70a1b1`, `6fa660e5`)
   The agents ran `ls docs/board/tasks` and it failed. The root `CLAUDE.md` names `docs/board/tasks/*.md` as the input format of fuda. It does not say that this repo's own tickets live in `.scratch/<feature>/issues/`.
   Ticket numbers also repeat per feature. "task 18" matched two files: `.scratch/fuda-writes/issues/18-desktop-distribution.md` and `.scratch/fuda-writes-build/issues/18-open-folder-in-the-web-ui.md`. The agent picked one without asking.
   Proposals: one line in `CLAUDE.md` that points to `docs/agents/issue-tracker.md` for this repo's tickets. Say there that numbers are per feature, and that an ambiguous number needs a question.

5. **UI change not tried in a browser.** (`08fe603e`)
   The agent said it had not looked at it. The user found the flicker.
   Proposal: a "check UI changes in the running app" step in `CONTRIBUTING.md`.

6. **PR body had no "How to test" and named the wrong path.** (`332bdacd`)
   The user asked twice for a "How to test" section and for the desktop build (`make desktop-macos`), not `make dev`.
   Proposal: a PR template with a required "How to test" heading.

7. **No written fork-and-PR steps.** (`332bdacd`)
   `origin` was another person's repository and the account had no write access. The agent asked, then forked.
   Proposal: a short section in `CONTRIBUTING.md`.

8. **`ctx-wire` skipped in most shell calls.** (`04d5e7ba`, `332bdacd`, `6fa660e5`, and this session in part)
   The rule sits in the user's global `~/.claude/CLAUDE.md`. Habit is weak against it. One agent (`1b70a1b1`) saw the output filter working without explicit `ctx-wire run` calls, so the evidence is mixed.
   Proposal: a hook that warns on raw `cat`, `head` and `tail`. Low value. Optional.

9. **Smaller items.**
   - Python string-replace scripts failed with `AssertionError` three times (`04d5e7ba`). Use `Read` then `Edit`.
   - macOS `sed` failed on a multi-line edit (`08fe603e`) and on `\|` (retro 1).
   - An unquoted `echo ======` failed in zsh (`1b70a1b1`).
   - A trailing `grep` or `tail` hid a real exit code (`04d5e7ba`).
   - A guess ("the key lives in `FUDA_CACHE_DIR`") went into `docs/decisions.md` unchecked (`6fa660e5`). Ticket 22 settled it.
   - The agent called `.claude/worktrees/` folders "empty" without `git worktree list` (`2542c2ee`). Fixed by `c9f2a4e`.

We left that on purpose: it is a safety rule.

- **Open, small:** finding 3 (a rule that `done` means no open boxes) and finding 9 (habit tips).
